本页是给**组织管理员 / 主编 / 总监**看的——介绍如何邀请团队成员、分配角色权限、删除离职用户,以及离职用户名下的资产(稿件、任务、媒资)如何转移。理解这些规则后,你能让团队的人员变动不影响内容生产链路。

## 角色体系

平台目前有 4 个内置角色,权限从大到小:

| 角色 | 主要权限 |
|---|---|
| **超级管理员(super_admin)** | 全部权限 + 跨组织 + 平台级配置 |
| **管理员(admin)** | 本组织内全部读写 + 用户管理 |
| **主编(editor)** | 内容生产 + 审核签发 + 看数据 |
| **作者(contributor)** | 写稿 + 提审 + 看自己的数据 |

也可以自定义角色——在 **系统管理 → 角色管理** 新建,勾选具体权限项。

## 邀请新成员

<Steps>
1. 进入 **系统管理 → 用户管理**
2. 点 **邀请成员**,填邮箱 + 选角色
3. 系统生成初始密码,你私下交给对方
4. 对方登录后改密码,即可开始使用
</Steps>

<Callout type="warn" title="平台不发邮件">
为了避免被钓鱼利用,平台**不发任何邮件**给新成员。初始密码必须通过你信任的私人渠道(IM / 当面)给到对方。这是有意的安全设计。
</Callout>

## 删除离职用户

人员变动时,**不要直接物理删除账号**——这会让历史稿件 / 任务的"作者"字段变成 NULL,审计追踪断链。推荐流程:

<Steps>
1. 在用户列表找到要离职的同事
2. 点 **转移资产**,选择接收人(通常是同岗位的另一个人)
3. 转移完成后再 **停用账号**(password_hash 置 NULL)
4. 停用后该账号无法登录,但历史记录的"创建者"字段保留为他
</Steps>

如果忘记转移就直接停用,稿件 / 任务的"创建者"字段会标记为 **已停用用户**,不会丢数据但后续追溯不方便。

## 重置密码

成员忘记密码时,**只有管理员能帮重置**:

<Steps>
1. 用户列表 → 找到对方账号 → **重置密码**
2. 设置新密码,私下交给对方
3. 对方登录后立即改密
</Steps>

详细的登录 / 密码机制见 <DocLink href="/help/getting-started/login-register">登录与注册</DocLink>。

## 审计日志

所有用户行为(登录、任务启动、稿件编辑、发布、用户管理)都会写入**审计日志**,保留 90 天。可在 **组织设置 → 审计日志** 按时间 / 操作类型筛选导出 CSV。需要更长保留期可联系超级管理员调整。

## 多组织

如果你的公司有多个事业部,可以**在一个平台实例下开多个组织(organization)**,组织间数据完全隔离。需要某个用户跨组织,在他的账号里"加入第二个组织"即可,登录后可在顶部切换。
