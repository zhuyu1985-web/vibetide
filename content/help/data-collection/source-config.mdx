数据采集是 Vibe Media 整个内容链路的"水源"。本页介绍如何添加和调试自定义采集源——RSS、网页爬虫、API 接口三种类型,以及常见失败原因排查。配置好采集源后,灵感池和主题监测的数据质量会显著提升。

## 三种采集类型

平台支持三种采集源类型,选哪种取决于目标站点暴露的数据接口:

| 类型 | 适用场景 | 配置难度 |
|---|---|---|
| **RSS** | 站点提供 atom/rss 订阅 | 低 |
| **网页爬虫** | 没有 RSS,需要解析 HTML | 中 |
| **API 接口** | 站点有公开数据 API | 中-高 |

## 添加新源的流程

进入 `/data-collection/source-config`,点击 **新增采集源**:

<Steps>
1. 选类型(RSS / 爬虫 / API)
2. 填基础信息:名称、URL、所属行业标签
3. 填类型特定字段:RSS 直接给地址、爬虫填 CSS 选择器或 XPath、API 填请求方法 + headers
4. 设置采集频率:5 / 15 / 30 / 60 分钟
5. 点 **测试运行**,看预览数据是否符合预期
6. 保存,激活采集
</Steps>

## TOP 5 失败原因

实际跑起来,采集失败是高频问题。**95% 的失败**集中在 5 个原因:

<Callout type="warn" title="对照排查清单">
1. **源站反爬升级**:UA / Cookie 失效,需要更新请求头
2. **限流**:同一 IP 触发频控,把采集间隔拉长 / 加并发限制
3. **接口下线**:第三方接口路径变了,系统会标红
4. **环境变量缺失**:`BOCHA_API_KEY` / `JINA_API_KEY` 没配
5. **页面结构异常**:HTML 不稳定,改用 Jina Reader 二次抓取
</Callout>

## Jina Reader 兜底

平台集成了 **Jina Reader**(`r.jina.ai`)做 HTML → Markdown 的稳定转换。当原生爬虫拿不到正文时,可以在采集源配置里**勾选"使用 Jina Reader 二次抓取"**。这会增加约 1-2 秒延迟,但显著提升正文完整率。

## 监控面板

所有采集源的运行状态在 **采集监控** 面板可视化:
- 24h 成功 / 失败次数
- 平均响应时间
- 失败率趋势曲线
- TOP 10 错误类型分布

发现某个源连续失败 24h,系统会自动**降权**(降频或暂停)并发邮件通知管理员。详细的 FAQ 见 <DocLink href="/help/faq">常见问题</DocLink>。

## 安全建议

<Callout type="warn" title="爬虫合规">
请遵守目标站点的 `robots.txt`、不要做高频高并发抓取、不要绕过付费墙、商用前确认数据使用权。
</Callout>
