技能(skill)是 AI 员工的核心能力单元。本页介绍技能的本质、如何给员工绑定 / 解绑技能、熟练度(proficiency)怎么计算,以及自定义技能的边界。理解技能机制后,你就能明白为什么同样一个员工跑同类任务会"越来越靠谱"。

## 技能本质上是什么

一个技能 = **prompt 模板 + 工具调用约定 + 输入输出 schema**。当员工"使用某个技能"时,系统做的事情是:

<Steps>
1. 把技能 prompt 模板装入员工的系统提示词
2. 注入员工绑定的知识库 + 相关记忆
3. 按 schema 校验输入参数
4. 调用 LLM 跑出结构化输出
5. 把执行结果回写到熟练度统计
</Steps>

所以"技能"不是一个孤立的 prompt,它和员工身份、知识库、记忆、工具权限**绑在一起**才能发挥作用。

## 在哪里管理技能

技能管理入口在 `/skills`。每个技能页面展示:

- **基础信息**:名字、描述、所属分类(skill_kind)
- **兼容员工**:哪些员工类型可以执行这个技能
- **输入 / 输出 schema**:参数定义
- **绑定的员工列表**:当前哪些员工已经绑定它

## 如何给员工绑定技能

进入员工详情页(`/ai-employees/[id]`),在 **技能** tab 勾选要绑定的技能即可。一个员工可以同时绑定多个技能,系统会在执行任务时**按熟练度优先级**选最熟的那个。

<Callout type="warn" title="技能不是越多越好">
盲目给员工堆技能反而拉低执行准确率。建议每个员工聚焦 5-8 个核心技能,围绕他的职责而不是"全栈通才"。
</Callout>

## 熟练度怎么计算

每次员工执行完技能,系统会做三件事:

- **+1 执行次数**(`practice_count`)
- 根据 LLM 自评分加权调整熟练度(0-100 分)
- 写入一条记忆(experience)用于后续相似任务

熟练度高的员工会被工作流编排时**优先选中**,新员工跑同一个技能可能要 10-20 次后才能追上老员工。这种"老员工有壁垒"的设计是有意的——让团队沉淀价值,而不是每个员工都从零开始。

## 自定义技能

平台允许**自定义技能**(`category=custom`),可以在 `/skills/new` 创建。建议步骤:

<Steps>
1. 先想清楚这个技能解决什么具体问题
2. 写好输入 / 输出 schema,确定参数边界
3. 在沙盒里跑 5-10 次,迭代 prompt
4. 标记 `compatibleEmployees`,只让相关员工能选用
5. 上线后观察前两周的执行成功率
</Steps>

更多协作示例见 <DocLink href="/help/ai-employees/employee-roster">AI 员工花名册</DocLink>。
