连接策略（src/db/index.ts）

// 本地 / 远程自动识别：本地直连开 prepare 享加速；远程 pooler 关 prepare 避免 PgBouncer 协议冲突
const isLocal = /\/\/[^/]*?(127\.0\.0\.1|localhost)/i.test(url);
const client = postgres(url, {
  prepare: isLocal,            // 本地 true / 远程 false
  connect_timeout: 10, idle_timeout: 300,
  max: 10, max_lifetime: 900,  // 首页一次并发 ~12 个查询
});
// globalThis 单例缓存 __db_client，避免 Next.js HMR 重复建连导致连接泄漏

Schema 迁移纪律（强制）

# 唯一标准流程——保证 schema 永远跟代码同步
# 1) 改 src/db/schema/*.ts
npm run db:generate   # 产出 SQL + 同步 meta/_journal.json + snapshot
npm run db:migrate    # 应用到当前 DATABASE_URL
⛔ 禁止

手工创建 YYYYMMDD_xxx.sql 日期文件（Drizzle 不追踪，迁库必漏）；绕过 Drizzle 直接 psql 改生产；手工编辑 _journal.json。

✅ 必做

一次变更 = 一次 db:generate + 一次 db:migrate；每次切换 DATABASE_URL / 迁库后立即跑 bash scripts/verify-schema-sync.sh（14 个 fingerprint 断言：核心表 / 字段 / 索引 / 枚举 / 废表已删）。

07 · Agent

AI Agent 系统

系统核心。位于 src/lib/agent/。每次员工工作前都会「装配」成一个带人格、技能、记忆、权限的 Agent，再以分层 System Prompt 驱动 LLM 执行。

装配流水线 assembleAgent()

  1. 并行加载 4 路数据（Promise.all）：员工 profile、该员工技能（join skills）、绑定知识库、confidence>0.3 按 importance 取 top-10 记忆。
  2. 记忆访问统计 fire-and-forget：accessCount+1、更新 lastAccessedAt。
  3. 计算熟练度：avgLevel = round(Σ skill.level / 技能数)，无技能默认 50。
  4. 加载技能内容：builtin 从 skills/<slug>/SKILL.md 文件读，custom/plugin 从 DB skills.content。
  5. 按权限过滤工具：observer→清空；advisor→仅 19 个只读工具；skillOverrides（意图驱动）→进一步收窄；有 KB 绑定且非 observer →自动追加 kb_search。
  6. 解析模型 + 构建分层 System Prompt。

分层 System Prompt（注释称 7 层，实际 9 段）

1身份姓名 / 昵称 / 职位；custom 员工追加自定义工作指令
2技能 + 熟练度列出可用工具；按熟练度三档给引导（≤30 严格按步 / ≤70 适当发挥 / >70 自由创新）
3真实性硬约束最高优先级：必须真调工具、严禁伪造来源/时间/数据、空结果如实说明（防幻觉合同）
4技能执行指南从 SKILL.md 抽「执行流程 + 输出规格」注入，截断 ~3000 字防膨胀
5权限声明 authorityLevel，超权限动作标「需要审批」
6知识背景注入绑定知识库的名称 + 描述
7敏感话题条件注入；涉及时需人工审核
8工作风格主动性 / 汇报频率 / 自主度% / 沟通风格 / 工作时间
9记忆 + 输出经验记忆；要求中文 Markdown、末尾附【质量自评 XX/100】+【输入参数不足】

执行 executeAgent()

  • 执行期才构建真实工具：createKnowledgeBaseTools + toVercelTools(...)，每个工具用 wrapToolExecuteWithContext 注入 org/operator/mission/task 上下文。
  • 注入时间基准：把「当前日期」写进 prompt，防 LLM 按训练截止日误判时效、给搜索设错时间窗。
  • skillSpec 硬约束：步骤绑定 SKILL.md 时，整篇 body pin 进 system prompt，强制三段式输出（执行摘要 / 执行过程 / 产出结果，各 ≥100 字）。
  • 调用：generateText({ stopWhen: stepCountIs(20), maxOutputTokens, abortSignal: AbortSignal.timeout(3min) })。
  • 失败检测：onStepFinish 扫 toolResults（AI SDK v6 用 .output 非 .result）收集 success:false，有失败则 override status="failed"（优先级高于 needs_approval）。
🛡 防幻觉是贯穿全系统的一等设计

多处真实事故驱动（伪造 WWDC 新闻、把「3 月 20 日」当 2024 年、反爬登录页被当正文入库）。五重防线：① Prompt 真实性硬约束层；② invokeToolDirectly 服务端直调工具（步骤显式绑参时绕过 LLM，结果不可伪造）；③ 工具 success:false 检测 override 状态；④ 检索类工具缺 API key 时显式 throw 让步骤标 failed 而非静默编造；⑤ 执行期注入真实时间基准。

08 · 意图

意图识别与模型路由

聊天中心用 AI 把用户消息解析成「该让谁、用哪些技能、按什么顺序做」；模型路由按技能类别选 provider 与温度。

意图识别 recognizeIntent()

  • Fast-path 跳 LLM：问候语正则 + 短文本阈值（≤6），直接返回 general_chat，confidence 0.95，省 token。
  • Prompt 构建：紧凑技能目录（按 category 列）、员工目录、工作流目录、用户历史 top-5 few-shot。
  • 检索类路由规则：问热榜→必须 trending_topics 禁 web_search；问进展→web_search；问 URL 正文→web_deep_read；问多平台扩散→trend_monitor。
  • 调用与兜底：temperature 0.2 / maxOutputTokens 1024，Promise.race 套 15 秒超时，超时回退自由聊天。
  • 输出校验：剥 markdown fence → JSON.parse → clamp confidence → 过滤非法 employeeSlug / skill slug → 校验 workflowId 决定 executionMode: "workflow" | "skill"。

另有 intent-parser.ts（旧版工作流意图解析，6 值 IntentType + 8 步默认 fallback），与聊天中心 recognizeIntent 是两套不同用途。

10 · 工作流

工作流与定时任务引擎

统一场景架构（B.1）：workflow_templates 表是所有「场景」的单一真相源。首页场景网格、任务中心都调 listWorkflowTemplatesByOrg。

核心 DAL（lib/dal/workflow-templates.ts）

  • listWorkflowTemplatesByOrg：org-scoped 富过滤；过滤「视觉上空」模板（steps 至少一个有效 skill）；性能修复——不 SELECT *、排除大 jsonb（steps 改返 stepsCount），列表查询从 14s 降到 1s。
  • seedBuiltinTemplatesForOrg：幂等 upsert，两路 onConflict（按 legacy_scenario_key 或 (org,name)），冲突时保留 org admin 手设的 is_public/is_enabled。
  • getByLegacyKey / create / update / softDisable。每 org 种子 27+ 内置模板。

12 个 category：news / deep / social / advanced / livelihood / podcast / drama / daily_brief / video / analytics / distribution / custom。启动 mission 时双写 scenario(slug) + workflowTemplateId(uuid FK)；builtin 的 slug = legacy_scenario_key，custom = custom_${nanoid(6)}。

⚠ 勘误

CLAUDE.md 提到的 src/lib/scenario-fallback.ts 实际不存在；场景显示名 fallback 内联在 leader-plan.ts（模板 name 优先于 scenario slug）。

定时任务（嫁接 scheduled_jobs · ADR-0002）

任意模板可挂 0..N 条 cron schedule，与手动启动并存。挂在 scheduled_jobs 表，用 kind='workflow_template' 区分平台级任务。Cron 校验（lib/cron.ts）强制相邻执行间隔 ≥ 60 秒（防 mission 启动风暴）。

// 触发链路
UI/action → schedules DAL → scheduled_jobs(kind='workflow_template')
  → scheduledJobsRunner (每分钟 cron 扫表)
  → 派 'scheduled-jobs/workflow-template.run' (deterministic jitter ±15s)
  → workflowTemplateScheduledLaunch handler
  → startMissionFromTemplateScheduled(templateId, orgId, inputs, {source:'schedule'})
// source.module='schedule' + sourceEntityId=jobId → missions_source_dedup_uidx 自动去重

12 · 知识库

知识库 RAG

src/lib/knowledge/。三件套：分块 → 嵌入 → 检索。V1 务实——jsonb 存向量 + 应用层余弦，明确标注 10k chunk 后升级 pgvector 的路径。

① 分块 chunking.ts

确定性策略：段落 → 句子 → 字符回退，贪心打包到 500–800 字，相邻 50 字 overlap。

② 嵌入 embeddings.ts

Jina jina-embeddings-v3，1024 维，批 100，指数退避重试；query/passage 用不同 task type。

③ 检索 retrieval.ts

searchKnowledgeBases(query, kbIds, topK=5)：并行生成 query 向量 + 拉候选，手写 cosine 降序取 topK。

  • 异步向量化：由 Inngest knowledge-base-vectorize 跑（监听 kb 文档创建 / 更新 / reindex），循环处理 embedding IS NULL 的 chunk。
  • Agent 集成：装配期为有 KB 绑定的员工注入 kb_search descriptor，执行期构真实现——限员工绑定 KB、只查 vectorization_status='done'、未完成加 warning 跳过。
  • 三种灌入：手动粘贴、md/txt 上传、URL 爬取（复用 Jina Reader）。

14 · 设计系统

设计系统约束与 ESLint

每一轮样式漂移都源于绕过共享原语。这套规则（含 ESLint 强制）让 UI 长期不走样。

必须用共享原语，禁止手搓

按钮→<Button>、输入→<Input>、搜索→<SearchInput>、下拉→<Select>、多行→<Textarea>、日期→<DatePicker>、Tabs→用 variant、表格→<DataTable>、标题→<PageHeader>、卡片→<GlassCard>。

  • 禁止在共享组件上用 className 覆盖颜色类（破坏 liquid-glass 风格），改用 variant。
  • 弹层内可滚动列表必须用固定高度 h-X 而非 max-h-X（避免搜索 / 切 tab / 增删时高度抖动）。
  • 项目特别约定：所有可点击触发事件的按钮 / 标签一律不带边框。
